# Хэндофф: Qt-пикер, довести до продакшена на рабочем ПК

Это инструкция для Claude Code, который откроет этот репозиторий на
рабочем ПК (там, где реально доступны ScaleX и CHITUBOX с принтерами —
дома при разработке этого PR доступа не было ни к тому, ни к другому).
Всё, что здесь написано, нужно **реально проверить руками/глазами**, а не
просто прочитать и поверить.

Контекст: `own_manager.py` был переписан с pywebview (embedded-браузер,
Edge WebView2) на нативные Qt-виджеты (PySide6) — см. PR #2
(`qt-picker-rewrite` ветка, ещё draft) и его описание для полного разбора
"зачем". Ветка уже запушена в GitHub, но **не смержена** — доработка
делается прямо в ней.

## 0. Подготовка

```bash
git fetch origin
git checkout qt-picker-rewrite
pip install PySide6
```

Убедитесь, что никакой другой `own_manager` (питоновский старый или
`own_manager_desktop.exe` на C/WebView2, если он ещё где-то остался) не
запущен параллельно — все версии борются за один и тот же discovery-хук
(`QSharedMemory`), выиграет тот, кто стартовал первым.

## 1. Реальные цвета ScaleX вместо заглушки (быстро, минут 5-10)

В `own_manager.py`, в самом начале секции с комментарием
`# --- Picker GUI ---`, найдите блок:

```python
COLOR_BG = "#14161a"
COLOR_PANEL = "#1c1f26"
COLOR_PANEL_2 = "#22262e"
COLOR_LINE = "#2c3038"
COLOR_TEXT = "#e6e8eb"
COLOR_TEXT_DIM = "#9aa1ab"
COLOR_ACCENT = "#3ddc84"
COLOR_RED = "#e5484d"
```

Это placeholder, подобранный на глаз дома, без сети до ScaleX. Замените
на настоящие значения:

1. Откройте `http://<scalex host>:<scalex port>/styles.css` в браузере
   (или через devtools на любой странице ScaleX — вкладка Network,
   найдите `styles.css`, посмотрите Response).
2. Найдите блок `:root { --bg: ...; --panel: ...; --accent: ...; ... }`
   в начале файла — это и есть исходные значения.
3. Сопоставьте по смыслу с `COLOR_*` выше (имена переменных в моём коде
   специально названы так же, как в реальном CSS, должно совпасть
   один-в-один по смыслу) и подставьте.
4. Если у ScaleX свой шрифт (не системный) — гляньте `font-family` в том
   же `styles.css`. Если это что-то стандартное типа Inter/Roboto и на
   рабочем ПК он не установлен, можно не гнаться за точным совпадением
   шрифта — цвета важнее.

Пересоберите (`python own_manager.py`) и сравните на глаз с реальным
ScaleX в браузере — не обязано быть пиксель-в-пиксель, но должно быть
явно "тот же цветовой язык", а не мой рандомный тёмный тон.

## 2. Реальный сквозной тест отправки (обязательно, это САМОЕ важное)

Это то, что **не было проверено** руками при написании PR — вся логика
отправки (`send_in_background`) не менялась и работает в проде через
старую версию, но путь "нажал чекбокс → Отправить → увидел прогресс на
карточке принтера" ни разу не кликался живьём на новом Qt-интерфейсе.

Шаги:

1. Запустите `python own_manager.py` из терминала (не через `pythonw`,
   чтобы видеть ошибки в консоли, если что-то упадёт).
2. Проверьте, что появилась иконка в трее.
3. В CHITUBOX нарежьте что-нибудь небольшое, нажмите «Отправка по сети».
4. Проверьте:
   - окно пикера открылось и само вышло на передний план (не пришлось
     руками кликать по таскбару);
   - список принтеров реально загрузился (не "Не удалось получить
     список");
   - если файл нарезан под конкретную модель — баннер "Нарезано под: ..."
     появился, и чекбокс "Подходит под файл" реально фильтрует список;
   - поиск, "Показывать включённые"/"Скрывать занятые" работают;
   - у принтеров с заданными рекомендациями показывается чекбокс
     "применить рекомендации" с текстом рекомендаций;
   - бейдж "Принтер подготовлен"/"Не подтверждён" совпадает с тем, что
     реально показывает сам ScaleX.
5. **Отметьте 1-2 некритичных/тестовых принтера**, галочку "Запустить
   печать" НЕ ставьте, нажмите «Отправить».
6. Проверьте:
   - у отмеченных принтеров под карточкой появился мини-прогресс-бар и
     **реально двигается** (это и есть непроверенная часть — если он
     просто висит на 0% или "В очереди" вечно, здесь баг);
   - в итоге показывает "Готово" или внятную "Ошибка: ...";
   - `C:\own_manager\own_manager.log` — там должна быть строка
     `=== PICKER: sending ... ===` и дальше нормальный лог отправки
     (`FORWARD TO SCALEX`/`PATCH+UPLOAD`/`UPLOAD STATUS`), без
     трейсбеков/исключений.
7. Если всё ок — повторите с одним принтером, у которого ЕСТЬ
   рекомендации, с включённой галочкой применения — убедитесь, что
   реально уходит `ctb/patch-and-upload`, а не обычная загрузка (видно
   по логу).
8. Если удобно/безопасно — повторите один раз с "Запустить печать сразу"
   и проверьте, что печать реально стартовала на принтере.
9. Закройте окно пикера **не отправляя** (крестиком) на отдельном
   тестовом файле — приложение не должно упасть, а следующая отправка из
   CHITUBOX должна открыть новое окно как ни в чём не бывало (трей
   держит процесс живым, `setQuitOnLastWindowClosed(False)`).
10. Проверьте пункты трея: "Отправить файл вручную…" (диалог выбора
    файла), "Открыть лог", "Выход".

## 3. Если что-то не работает

- Если баг **явный и локальный** (опечатка, не тот цвет, забыли текст) —
  чините на месте, коммитите в эту же ветку.
- Если баг похож на **threading/сигналы** (окно подвисает, прогресс не
  обновляется, краш при закрытии) — не гадайте вслепую, это именно тот
  класс проблем, который дорого чинить наугад (см. историю двух прошлых
  реальных зависаний в этом же проекте). Соберите: точный сценарий
  воспроизведения, хвост `own_manager.log`, и если есть traceback в
  консоли — его тоже. С этим возвращайтесь (опишите новому Claude Code
  дома или продолжите тут сами, конкретные факты решают всё).

## 4. Когда всё проверено

1. Уберите пометку draft у PR #2 (`gh pr ready` или кнопка на GitHub).
2. Смержите в `main`.
3. Автозапуск: `own_manager_autostart.vbs` уже настроен на
   `pythonw.exe own_manager.py` — трогать не нужно, но убедитесь, что в
   том же Python-окружении (том, что видит `pythonw.exe` из автозагрузки)
   тоже стоит `PySide6` (`pip install PySide6`), не только в том, из
   которого вы тестировали руками.
4. Опционально: удалите/заархивируйте `own_manager_desktop.c` и
   `own_manager_desktop.exe` (C/WebView2-версия) из обихода, если Qt
   версия признана основной — она была промежуточным экспериментом.
